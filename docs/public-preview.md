# Public preview mode — โครงสร้างเว็บฝั่งผู้ใช้ทั่วไป

เอกสารออกแบบ ไม่ใช่โค้ด สำหรับตัดสินใจก่อนลงมือ

## 1. ปัญหาที่แก้

ตอนนี้ทุกคนที่เปิด `https://<site>/` เจอหน้า Sign in ทันที เพราะ:

- `web/src/App.tsx` บรรทัด ~506: `if (!approved) return <Login/>` — ไม่มีเส้นทางอื่นออกจากหน้านั้น
- `backend/app/api/v1/router.py` บรรทัด 64–72: `signed_in = [Depends(require_user), Depends(deny_collector_accounts)]` ครอบ `areas`, `dashboard`, `tiles`, `cells`, `reports`, `sites`, `exports`, `weak_areas` ทั้งก้อน
- บัญชีใหม่เกิดมาเป็น `pending` (`auth.py: upsert_user_from_claims`) และต้องรอ super admin กด approve

แปลว่าแม้กรรมการจะยอมล็อกอินด้วย Google ก็ยัง **เห็นแค่หน้า "รออนุมัติ"** อยู่ดี ต้องมีคนคอยกดอนุมัติสด ๆ ระหว่างการนำเสนอ ซึ่งเป็นความเสี่ยงที่ไม่ควรมี

> เป้าหมาย: คนแปลกหน้าเปิดลิงก์แล้วเห็นแผนที่จริงกับตัวเลขจริงภายใน 5 วินาที โดยไม่ต้องพิมพ์อะไรเลย ส่วนสิ่งที่เป็นข้อมูลอ่อนไหวยังปิดเหมือนเดิม

## 2. หลักการตัดสิน: อะไรเปิด อะไรปิด

เกณฑ์ไม่ใช่ "ข้อมูลนี้สวยไหม" แต่คือ **ข้อมูลนี้ชี้ตัวใครได้ไหม และเป็นความลับทางธุรกิจของใครหรือเปล่า**

| ข้อมูล | สาธารณะ | เหตุผล |
| --- | --- | --- |
| Coverage hexagon (H3 res 8, รวมทุกเครือข่าย) | ✅ | เป็นค่ารวมอยู่แล้ว และ `tile_min_devices = 2` บังคับให้ต้องมีอย่างน้อย 2 เครื่องต่อ tile — ชี้ตัวคนเดินคนเดียวไม่ได้ |
| ตัวเลขหลักระดับประเทศ (measurements, พื้นที่ที่วัดแล้ว, % ของประเทศ, จุดไม่มีสัญญาณ, อัปเดตล่าสุด) | ✅ | คือข้อความหลักของโครงการ และเป็นสิ่งที่พิสูจน์ว่านี่ไม่ใช่ mockup |
| ขอบเขตพื้นที่ปกครอง + coverage รายแขวง/เมือง | ✅ | ขอบเขตเป็นข้อมูลเปิด ส่วน coverage เป็นค่ารวมของ hexagon ที่เปิดอยู่แล้ว |
| หน้าอธิบายวิธีวัด (Method) | ✅ | ไม่มีข้อมูล มีแต่วิธีการ — และช่วยให้กรรมการเชื่อถือตัวเลข |
| แยกรายเครือข่าย (Unitel / LTC / ETL / TPlus) | ❌ | ส่วนแบ่งคุณภาพสัญญาณรายค่ายเป็นข้อมูลอ่อนไหวเชิงธุรกิจ และ `operator_scope` ทั้งระบบสร้างมาเพื่อกันเรื่องนี้ |
| ตำแหน่งเสา / cells | ❌ | โครงสร้างพื้นฐานของผู้ให้บริการ |
| Collector fleet + ตำแหน่งเครื่อง | ❌ | เป็น telemetry ของอุปกรณ์ที่ผูกกับคน |
| Priority areas / weak areas ranked | ❌ | เป็นข้อเสนอเชิงลงทุน ควรอยู่หลังบัญชี (เปิดทีหลังได้ถ้าอยากโชว์) |
| exports, /mine, /users, changes, reports | ❌ | ไม่มีเหตุผลให้เปิด |

ข้อสังเกตที่ควรพูดกับกรรมการตรง ๆ: **หน้าสาธารณะจงใจไม่แยกรายค่าย** นี่ไม่ใช่ข้อจำกัดทางเทคนิค แต่เป็นการออกแบบ และเป็นคำตอบที่ดีเวลาถูกถามว่า "แล้วผู้ให้บริการจะยอมให้ข้อมูลไหม"

## 3. ฝั่ง backend: router `/public` แยกต่างหาก

### 3.1 ทำไมไม่ถอด `require_user` ออกจาก router เดิม

เพราะ `router.py` เขียนไว้ดีอยู่แล้วว่า *deny by default* — endpoint ใหม่ที่ใครเพิ่มเข้า `tiles.py` พรุ่งนี้จะถูกปิดโดยอัตโนมัติ ถ้าไปถอด dependency ออกจากรายการนั้น กฎข้อนี้หายไปทั้งระบบ และบทเรียนที่คอมเมนต์ในไฟล์เล่าไว้ (endpoint หนึ่งลืม scope แล้วบัญชีค่ายหนึ่งเห็นเสาของคู่แข่ง) จะเกิดซ้ำ

router ใหม่ทำให้:

1. รายการสิ่งที่เปิดสาธารณะเป็น **allowlist ที่อ่านได้ในไฟล์เดียว**
2. ตัด field ที่ละเอียดเกินออกได้โดยไม่กระทบ client ฝั่ง admin
3. ใส่ rate limit / cache แยกได้ เพราะโหลดคนละแบบกัน

### 3.2 โครงไฟล์

```
backend/app/api/v1/
  public.py          ← ใหม่: allowlist ทั้งหมดอยู่ที่นี่
  router.py          ← เพิ่มบรรทัดเดียว: include public.router (ไม่มี dependencies)
```

```python
# router.py — วางไว้ในกลุ่ม "Open" พร้อมคอมเมนต์ว่าทำไม
# เปิด: หน้าตัวอย่างสาธารณะ ทุก endpoint บนนี้ตอบข้อมูลรวมเท่านั้น
# ไม่มีรายเครือข่าย ไม่มีตำแหน่งเครื่อง ไม่มีอะไรที่ชี้ตัวใครได้
api_router.include_router(public.router)
```

### 3.3 Endpoint

| Method | Path | ตอบอะไร |
| --- | --- | --- |
| GET | `/api/v1/public/summary` | ตัวเลขหลัก (ตัดมาจาก `coverage_summary`) |
| GET | `/api/v1/public/tiles?min_lat=&min_lon=&max_lat=&max_lon=` | hexagon ในกรอบภาพ รวมทุกเครือข่าย |
| GET | `/api/v1/public/areas?level=` | รายชื่อแขวง/เมือง สำหรับ dropdown และ choropleth |
| GET | `/api/v1/public/areas/{code}` | ขอบเขต + coverage ของพื้นที่เดียว |
| GET | `/api/v1/public/areas/{code}/children` | choropleth ระดับลูก |

ทุกตัว **ห้ามรับพารามิเตอร์ `operator`** — ไม่ใช่ "รับแล้วปฏิเสธ" แต่คือไม่มีในลายเซ็นฟังก์ชันเลย จะได้ไม่มีทางเผลอส่งต่อ

### 3.4 ตัด field ที่ละเอียดเกินออก

`tiles.py::_feature(tile, detailed=…)` วันนี้ส่ง `device_count`, `sample_count`, ค่า RSRP ละเอียด ฯลฯ ฝั่ง public ควรมีแค่:

```
h3_index, geometry, dominant_state, colour,
measured (bool), is_predicted (bool), updated_at
```

เหตุผล: `device_count = 2` บวก `updated_at` บวกตำแหน่ง hexagon เริ่มเข้าใกล้ "ใครไปที่นั่นตอนไหน" ซึ่งเป็นสิ่งเดียวกับที่ `retention_precise_days` ตั้งใจกันไว้

ทำเป็นฟังก์ชันแยก `_public_feature(tile)` ใน `public.py` ไม่ใช่ flag ตัวที่สามใน `_feature` — flag ที่สามคือที่ที่ความผิดพลาดชอบซ่อนตัว

### 3.5 ข้อจำกัดและการป้องกัน

```python
# public.py
PUBLIC_MAX_BBOX_DEGREES = 3.0     # แคบกว่าฝั่งใน (6.0) — ป้องกันการ scrape ทั้งประเทศในคำขอเดียว
PUBLIC_MAX_FEATURES = 4000        # เกินนี้ตอบ 400 พร้อมข้อความว่าให้ซูมเข้า
CACHE_SECONDS = 60                # เท่ากับรอบ aggregation — เร็วกว่านี้คือถามคำถามเดิม
```

- ตอบ header `Cache-Control: public, max-age=60` ทุกตัว nginx และ CDN จะรับภาระแทน API ตอนกรรมการหลายคนเปิดพร้อมกัน
- Rate limit ต่อ IP (เช่น 60 req/นาที) — ใช้ `slowapi` หรือ middleware สั้น ๆ ก็พอสำหรับ pilot
- Feature flag ใน `core/config.py`:

```python
# เปิดหน้าตัวอย่างสาธารณะหรือไม่ ค่าเริ่มต้นเปิด เพราะทั้งจุดประสงค์ของมัน
# คือให้คนที่ไม่มีบัญชีเห็นได้ ปิดได้ด้วย PUBLIC_PREVIEW_ENABLED=false
# ถ้าวันหนึ่งเจ้าของข้อมูลขอให้ปิด
public_preview_enabled: bool = True
```

ถ้าปิด ทุก endpoint ใน `/public` ตอบ 404 (ไม่ใช่ 403 — 403 บอกว่ามันมีอยู่)

### 3.6 CORS

หน้าสาธารณะเสิร์ฟจาก origin เดียวกันผ่าน nginx อยู่แล้ว จึงไม่ต้องแก้ `cors_origins` ถ้าจะให้เว็บอื่น embed แผนที่ ค่อยเพิ่มทีหลัง และเพิ่มเฉพาะ `/public`

## 4. ฝั่ง client: SPA เดียว มี route สาธารณะ

### 4.1 ตารางเส้นทาง

| Path | หน้า | ใครเข้าได้ |
| --- | --- | --- |
| `/` | Landing / pitch | ทุกคน |
| `/map` | แผนที่สาธารณะ | ทุกคน |
| `/method` | วิธีการวัด | ทุกคน |
| `/signin` | หน้าเข้าสู่ระบบ | ทุกคน |
| `/pending` | "บัญชีรออนุมัติ" | ล็อกอินแล้วแต่ยังไม่ approve |
| `/app` | → redirect ไป `/app/map` | approved |
| `/app/map` | แผนที่เต็ม (ตัวกรองครบ, เสา, weak areas) | approved |
| `/app/overview` `/app/priority` `/app/networks` `/app/collectors` `/app/method` | ตามเดิม | approved (บาง path ปิดสำหรับ operator) |
| `/app/mine` | ข้อมูลของฉัน | collector |
| `/app/users` | จัดการผู้ใช้ | super_admin |

`web/nginx.conf` มี `try_files $uri $uri/ /index.html;` อยู่แล้ว → deep link ทำงานได้ทันที ไม่ต้องแก้

**Router**: เพิ่ม `react-router-dom` (ประมาณ 20 kB gzip) หรือเขียน router เล็ก ๆ ~60 บรรทัดบน `history.pushState` เองก็ได้ ถ้าอยากคง dependency ไว้แค่ 3 ตัวเหมือนเดิม แนะนำ `react-router-dom` เพราะ `useSearchParams` จะมีประโยชน์ตอนทำ deep link ไปยัง hexagon หรือแขวงหนึ่ง (`/map?area=01`) ซึ่งเป็นสิ่งที่กรรมการชอบกด

### 4.3 SessionProvider แทนที่ if สองชั้นใน App.tsx

วันนี้:

```tsx
if (session === null) return <div className="boot">…</div>;   // ทุกคนรอ
if (!approved)        return <Login … />;                      // ทุกคนโดนบล็อก
```

ใหม่ — session กลายเป็น 4 สถานะ และ **หน้าสาธารณะไม่รอมันเลย**:

```tsx
type SessionStatus = "loading" | "anonymous" | "pending" | "approved";
```

- `/` และ `/map` render ทันที ไม่ต้องรอ `/auth/session` — นี่คือเหตุผลหลักที่หน้าแรกจะเร็วขึ้นมาก เพราะวันนี้ทุกคนรอ round trip หนึ่งรอบก่อนเห็นอะไรเลย
- `RequireApproved` เท่านั้นที่รอ `loading` แล้วค่อยตัดสิน
- ปุ่ม "เข้าสู่ระบบ" มุมขวาบนอ่านค่า session แบบ background: ถ้า approved อยู่แล้วเปลี่ยนเป็น "ไปที่แดชบอร์ด" — คนที่ล็อกอินค้างไว้จะไม่ต้องล็อกอินซ้ำ

### 4.4 PublicMap ใช้ MapView ตัวเดียวกัน ต่างที่ props

```tsx
<MapView
  tiles={tiles}              // จาก /public/tiles
  summary={summary}          // จาก /public/summary
  basemap={basemap}          // สลับ streets/satellite ได้ — ไม่มีข้อมูลอ่อนไหว
  terrain={terrain}
  childAreas={childAreas}    // choropleth ระดับแขวง
  areaOutline={areaOutline}
  collectors={[]}            // ปิด
  cells={EMPTY_GEOJSON}      // ปิด
  weakAreas={EMPTY_GEOJSON}  // ปิด
  showWeakAreas={false}
  onBoundsChange={loadPublicTiles}
  onSelect={setSelected}     // เปิดได้ แต่แผงข้างแสดงเฉพาะ field สาธารณะ
/>
```

สิ่งที่ต่างจาก `/app/map` ในสายตาผู้ใช้: ไม่มี dropdown เครือข่าย ไม่มีตัวกรอง 5 สถานะ ไม่มีปุ่ม weak areas ไม่มีหมุดเสา ไม่มีแถบ live/collectors — เหลือแผนที่ + legend + ตัวกรองพื้นที่ + ปุ่ม 3D

`TileInspector` ฝั่งสาธารณะควรเป็นคนละคอมโพเนนต์เล็ก ๆ (`PublicTileCard`) ที่แสดงแค่ สถานะ, สี, "วัดเมื่อ" — ไม่ใช่ตัวเดิมที่ซ่อน field เพราะการซ่อนใน UI ไม่ได้แปลว่าไม่ได้ส่งมา

### 4.5 แบนเนอร์บอกสถานะ ไม่ใช่ประตูปิด

บน `/map` มีแถบบาง ๆ ด้านบน:

> 🔓 **โหมดตัวอย่างสาธารณะ** — ข้อมูลรวมระดับ hexagon ทุกเครือข่าย
> ดูรายเครือข่าย ตำแหน่งเสา และรายการพื้นที่ควรลงทุน → *เข้าสู่ระบบ*

หลักการ: **บอกว่ามีอะไรอยู่ข้างหลัง ไม่ใช่แค่บอกว่าเข้าไม่ได้** กรรมการอ่านแล้วรู้ทันทีว่าระบบมีมากกว่าที่เห็น ซึ่งดีกว่าปล่อยให้เดา และดีกว่าให้เจอกำแพงเปล่า

ปุ่มที่ล็อกอยู่ในหน้าสาธารณะไม่ควร "หายไป" ทั้งหมด — แสดงเป็นชิปสีจาง มีไอคอนกุญแจ กดแล้วไป `/signin?next=/app/map` วิธีนี้ทำให้หน้าสาธารณะทำหน้าที่เป็นสาธิตความสามารถของระบบไปด้วยในตัว

- **แผนที่ย่อในหน้าแรกต้องกดได้จริง** ไม่ใช่ภาพนิ่ง สิ่งที่ทำให้คนเชื่อคือได้ลากแผนที่เองแล้วเห็น hexagon ขยับ
- **ตารางสถานะจริง** (ส่วนที่ว่า ML ยังไม่เริ่ม) เป็นสิ่งที่ README ทำไว้แล้วและควรยกขึ้นเว็บ กรรมการ hackathon ให้คะแนนความซื่อสัตย์มากกว่าการอวด และมันกันคำถามยาก ๆ ล่วงหน้า
- **ปุ่มหลักคือ "ดูแผนที่สด" ไม่ใช่ "เข้าสู่ระบบ"** ปุ่มเข้าสู่ระบบอยู่มุมขวาบน ขนาดปกติ ไม่เด่น
- ทำงานได้บนมือถือ — กรรมการหลายคนเปิดจากโทรศัพท์ระหว่างเดิน

## 6. เส้นทางที่กรรมการเดิน (ทดสอบด้วยเส้นทางนี้)

1. เปิดลิงก์ในหน้าต่างไม่ระบุตัวตน → เห็น Landing พร้อมตัวเลขจริงภายใน ~2 วินาที
2. กด "ดูแผนที่สด" → แผนที่โหลด hexagon ในกรอบภาพ ไม่มี 401 ใน console
3. ซูมไปเส้นทาง 13 เหนือ → เห็นช่วงสีแดงจริง กดที่ hexagon → เห็นสถานะและเวลาที่วัด
4. กด "วิธีการวัด" → อ่านได้โดยไม่ต้องล็อกอิน
5. กด "เข้าสู่ระบบ" → เห็นหน้าล็อกอินที่บอกชัดว่าเข้าไปแล้วได้อะไรเพิ่ม
6. กด Back → กลับหน้าเดิม ไม่ใช่เด้งไปหน้า sign in

ข้อ 6 คือข้อที่พังบ่อยที่สุดเวลาทำ guard — ทดสอบด้วย

## 7. Checklist ความปลอดภัยก่อน deploy

- [ ] เปิด DevTools → Network ในหน้าต่างไม่ระบุตัวตน กด `/` และ `/map` ทุกคำขอต้องขึ้นต้นด้วย `/api/v1/public/` หรือ `/api/v1/auth/session` เท่านั้น
- [ ] `curl` ทุก endpoint เดิมโดยไม่มีคุกกี้ ต้องได้ 401 ทั้งหมด: `/tiles` `/areas` `/dashboard/summary` `/dashboard/collectors` `/cells` `/weak-areas` `/sites` `/exports` `/mine/*` `/users`
- [ ] `/public/tiles` ไม่มี field `device_count`, `sample_count`, ค่า RSRP ดิบ
- [ ] `/public/tiles?operator=Unitel` — พารามิเตอร์ถูกละเลย (ไม่ใช่ตอบข้อมูลรายค่าย)
- [ ] `/public/tiles` ด้วย bbox ทั้งประเทศ → 400 พร้อมข้อความให้ซูมเข้า
- [ ] response ของ `/public/*` มี `Cache-Control: public, max-age=60`
- [ ] `PUBLIC_PREVIEW_ENABLED=false` → `/public/*` ตอบ 404 และหน้าเว็บกลับไปเป็นแบบเดิม
- [ ] **pytest ตัวใหม่**: วนทุก route ใน `app.routes` แล้ว assert ว่า path นั้นอยู่ใน allowlist ที่เขียนไว้ในเทสต์ หรือมี `require_user` อยู่ใน dependencies — เทสต์นี้จะพังทันทีที่มีคนเพิ่ม endpoint ใหม่โดยไม่คิดเรื่องสิทธิ์ ซึ่งคือสิ่งที่อยากให้เกิด

## 8. ลำดับการลงมือ

| ขั้น | งาน | ได้อะไร |
| --- | --- | --- |
| 1 | `public.py` + include ใน router + เทสต์สิทธิ์ | เรียก `/public/summary`, `/public/tiles` ได้ด้วย curl โดยไม่มีคุกกี้ |
| 2 | เพิ่ม router + `SessionProvider` + `RequireApproved`, ย้าย `App.tsx` → `admin/AdminShell.tsx` | ของเดิมทั้งหมดยังทำงานที่ `/app/*` พฤติกรรมไม่เปลี่ยน |
| 3 | `PublicMap` + `StatStrip` + `PreviewBanner` ที่ `/map` | เป้าหมายหลักสำเร็จแล้วตั้งแต่ขั้นนี้ |
| 4 | `Landing.tsx` | หน้าแรกที่ใช้พรีเซนต์ได้ |
| 5 | `/method` สาธารณะ, i18n ครบ ลาว/อังกฤษ, ตรวจบนมือถือ | เก็บงาน |

ขั้น 1–3 คือสิ่งที่แก้ปัญหาที่ตั้งไว้ ขั้น 4–5 คือสิ่งที่ทำให้ชนะ ถ้าเวลาไม่พอให้ตัดขั้น 5 ก่อน ไม่ใช่ขั้น 4

ทุกขั้นเป็น commit ที่ deploy ได้เอง และย้อนกลับได้เอง — ถ้าเกิดปัญหาระหว่างวันนำเสนอ `PUBLIC_PREVIEW_ENABLED=false` คือปุ่มถอยที่ไม่ต้อง redeploy

## 9. สิ่งที่จงใจไม่ทำ

- **บัญชี demo ที่แชร์รหัสผ่าน** — แก้ปัญหาผิดจุด กรรมการยังต้องพิมพ์อยู่ดี และรหัสที่แชร์แล้วเรียกคืนไม่ได้
- **auto-approve บัญชี Google ทุกคน** — เท่ากับเปิดข้อมูลรายค่ายให้คนทั้งอินเทอร์เน็ต แย่กว่าโหมดสาธารณะที่คุมขอบเขตได้
- **ลิงก์ลับที่มี token ใน URL** — token ที่อยู่ใน URL จะไปโผล่ใน history, ใน referer, ในสไลด์ที่ฉายขึ้นจอ
- **แยกเว็บเป็นสอง app** — ต้องดูแล build, nginx, i18n, สไตล์ สองชุด แลกกับความปลอดภัยที่ได้เพิ่มไม่มาก เพราะเส้นแบ่งจริงอยู่ที่ API ไม่ใช่ที่ bundle
